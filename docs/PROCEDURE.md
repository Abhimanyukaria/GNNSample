# gnnsample — reproduction procedure

Step-by-step from a fresh machine to the numbers in [`decisions.md`](decisions.md).
This copy ships **code only**: `data/raw`, `data/csc`, `results/` and the kernel cache
`.gpu_cache/` are regenerated by the steps below. Design and invariants are in
[`ARCHITECTURE.md`](ARCHITECTURE.md); agent rules are in [`../CLAUDE.md`](../CLAUDE.md).

## 0. Prerequisites

- An Intel GPU (developed on an Intel Core Ultra iGPU) with Docker + GPU passthrough
  (Docker Desktop on WSL2 was used). Other SYCL devices need a different `-DCMAKE_*`
  target; see `CMakeLists.txt`.
- The `gridguard:latest` base image, built from the sibling `GridGuard` folder
  (`docker compose build` there).
- Windows + Git Bash: prefix `docker compose run` with `MSYS_NO_PATHCONV=1`; if the
  Docker CLI is not on PATH, uncomment the PATH line in `tools/*.sh`.
- Plug in AC power before any benchmark: timings on battery are not comparable.

## 1. Build

```bash
docker compose build
docker compose run --rm -T dev cmake -B build -G Ninja -DCMAKE_CXX_COMPILER=icpx
docker compose run --rm -T dev cmake --build build
```

Output: `python/gnnsample/_C*.so`. The first GPU run JIT-compiles kernels into
`.gpu_cache/` (about 10 minutes); later runs reuse it.

## 2. Datasets

```bash
docker compose run --rm -T dev sh data/prepare_small.sh
```

Downloads products (OGB), LiveJournal and Orkut (SNAP) into `data/raw/` and converts each
to the binary CSC layout in `data/csc/<name>/` (`data/prepare.py <name>` does one).
Twitter is optional and large: `tools/convert_twitter.sh`, then `data/finish_twitter.py`
to validate and write its `meta.json`.

## 3. Correctness

```bash
sh tools/run_logged.sh test 1800 python -m pytest -q tests/
```

72 tests, about a minute; they need the GPU. The bar is bit-identity with
`python/gnnsample/reference.py` for every sampler path and option combination.

## 4. Benchmarks

Every long run goes through `tools/run_logged.sh <name> <timeout_s> <cmd>` (hard
timeout, log in `results/logs/`, power state recorded). In a second terminal:

```bash
sh tools/watch_runs.sh 300
```

prints STALL / DONE / GONE every 5 minutes. Never run two GPU benchmarks at once.

| What | Command | Writes |
|---|---|---|
| Per-option ablation (paired, interleaved) | `sh tools/run_logged.sh ablate-x 2400 python bench/ablate.py --graph products --variants 8169,0` | `results/ablation.jsonl` |
| End-to-end training step | `sh tools/run_logged.sh e2e-ours 1800 python bench/train_e2e.py --config ours-overlap` | `results/train_e2e.jsonl` |
| Full suite (build, tests, per-dataset sampler vs v1 and pyg-lib, stage times, CPU vs pyg-lib, end-to-end) | `sh tools/bench_suite.sh` (`-d "products orkut"`, `--accuracy` ~55 min, `--twitter`, `--quick` smoke test) | `results/suite/iteration_<x>.md`, raw files in `results/suite/iter_<x>/` |
| Accuracy parity | `python bench/accuracy.py --sampler ours --seed 0` and `--sampler pyg --seed 0` (repeat per seed), then `python bench/accuracy_report.py` | `results/accuracy/<sampler>_seed<k>.json` |

Other scripts in `bench/` reproduce the individual studies cited in `decisions.md`
(gather, latency anatomy, locality, memory, CPU scaling, reorder, multi-batch); each
`D<n>` entry names the script and log it came from.

## 5. Reporting a result

Use paired measurements only (`bench/ablate.py` interleaves variants in one process);
report the median per-batch ratio on products, LiveJournal and Orkut; record it as a new
`D<n>` entry in `decisions.md` with reason, alternative, numbers and log path.
